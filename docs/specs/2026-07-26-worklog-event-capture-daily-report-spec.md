# worklog 事件捕获式个人日报系统设计规格

日期:2026-07-26
状态:设计定稿,待实现
取代:power-work-report V1 的考古式采集设计(其代码资产按 FR-14 迁移复用)

## 背景

原始需求本体:让 AI 自动整理每天做了什么,记录已完成事项与新增待办,并顺手收集想法。当前工作大部分在 Codex 会话中完成,但这是数据源的偶然,不是需求的本质。

现有 power-work-report V1 采用纯考古式方案:日终扫描 Codex rollout JSONL,用关键词启发式反推用户意图。审查结论:工程质量高(时区处理、HTML 转义、行为测试),但架构上把智力花在"从噪声里可靠地重建一天",而重建必然丢失意图,导致过采与漏采并存、确认噪声大。

本设计将重心移到"让这一天在发生时就把自己记下来":即时捕获为主干,日志考古降级为兜底。这是数据工程问题到习惯设计问题的转向。

## 目标

- 每日以不超过一分钟的确认成本,产出一屏可读的日报,并维护持续的待办与想法账本。
- 捕获与提醒对日常编码工作的污染在干净状态下为零字节。
- 系统在零 LLM 配置下完整可用;LLM 仅作为可拔插的判断层。
- 数据源可插拔;Codex 与 git 是首批采集器,不是架构假设。

## 核心原则

1. **账本是唯一资产,其余一切可再生。** 日报、草稿、review、HTML 全部是账本的视图或缓存,删除后可重建。保护等级按"写坏了会不会心疼"分配。
2. **在发生时捕获;考古是兜底,不是主干。** 捕获的原子是事件,不是会话——事件带自己的时间戳,与会话跨几天无关。
3. **确认成本决定系统生死。** 一分钟预算同时是用户时间预算和上下文卫生预算。一手记录默认通过,只有捞漏与完成候选需要点头。
4. **LLM 只放在判断点上。** 模糊匹配与两三句概览是仅有的两个模型面;失败或未配置时走确定性降级,主干不依赖模型。
5. **本地优先、最小爆炸半径。** 不建 daemon、数据库、向量库、服务端;全部人类可读文本;整个目录可作为私有 git 仓库获得历史、备份与同步。
6. **热路径全 bash,冷路径才用 Node/Python。** 分界线是调用频率:每 prompt、每 commit、每次随手记的路径必须毫秒级、零依赖;每天一次的装配与提交可以用重语言并复用现有资产。
7. **一天以人为准。** 日报单位是用户经历的本地日;事件时间戳经时区映射归日,跨午夜长会话按事件切分(继承 V1 的时区工程与测试)。
8. **对主工作的纪律随载荷走,不常驻。** 提醒的行为约束写在注入体内,只在有欠账的那一次注入中存在;全局常驻指令仅允许一行(口头捕获触发词)。
9. **写入纪律内建为代码,不指望提示词记得执行。** 原子替换、幂等事务、快照重放由提交器实现,而非由技能文本约定。

## 需求

### 功能需求

#### FR-1:存储布局与一致性承诺

根目录 `~/.worklog/`(名称待定,见待定决策),三个区、三种承诺:

```
~/.worklog/
  inbox.jsonl          # WAL:只追加,永不改写,单行小写入近似原子
  ledger/
    ledger-log.jsonl   # 事务日志:每笔已确认结算追加一条,只追加
    ledger.json        # 状态快照:临时文件写完 rename 原子替换
  days/
    2026-07-25/
      day.json         # 当日装配结果与确认记录(数据本体)
      report.md        # 日报正典视图
      report.html      # 可选视图
  git-hooks/           # core.hooksPath 指向的全局 git 钩子
```

- inbox:只追加。任何组件不得改写或删除其中的行。
- ledger:快照损坏时必须可由 ledger-log 重放重建;提供 `wl rebuild` 命令执行重放。
- days:缓存定位,任何文件可由 ledger 与 inbox 重新渲染。
- 全部文件为 UTF-8 人类可读文本。`~/.worklog` 自身可初始化为私有 git 仓库,系统不内置同步。

#### FR-2:事件模型

inbox 每行一个 JSON 对象,由 `wl` CLI 统一生成,字段:

```json
{"ts":"2026-07-25T14:32:05+08:00","type":"done","text":"修复授权衰减边界判定",
 "project":"ohmypowers","source":"commit:a3f2c19"}
```

- `type` ∈ done | todo | idea | note。
- `source` 形如 `commit:<sha>` | `session:<id>` | `manual` | `archaeology:<collector>:<ref>`(最后一种仅存在于候选,不落 inbox)。
- JSON 组装必须经 `jq -n --arg` 之类的正规转义,禁止字符串插值手拼。
- 三个写入者共享 `wl` 这一个咽喉点:锁、格式、时间戳、转义只实现一次。

#### FR-3:捕获链触发点

**① git commit(机械,主承重)。** `git config --global core.hooksPath ~/.worklog/git-hooks` 一次配置全局生效;`post-commit` bash 脚本取 `git log -1` 的 sha、subject、仓库名,调 `wl done --source commit:<sha>`。merge commit 跳过;rebase/amend 产生的重复不在钩子处理,由装配器按 sha 去重——钩子只管傻写。

**② 口头触发词(半机械,唯一常驻指令)。** 用户说出固定触发词("记一下 / 记个待办 / 记个想法")时,agent 立即执行对应 `wl` 命令并继续当前任务。该指令是全局 AGENTS.md 中本系统唯一的一行。触发词固定,不允许 agent 自由判断某句话"像不像想法"——判断权在用户,这是防过采集的闸门。失败模式可见(工具调用可见),用户可当场补催或自己在终端执行。

**③ agent 交付 tee(尽力而为)。** power-gan 交付收尾报告 outcome 的同时执行 `wl done --source session:<id>`,在其 SKILL.md 交付段追加一句实现。不指望百分百;漏掉的交付以 commit(①)或会话日志(FR-5 捞漏)的形式留下痕迹,三层互为冗余。

#### FR-4:wl CLI

- bash 实现,零依赖(允许调用 jq / python3 做 JSON 转义),启动毫秒级。
- 子命令:`done / todo / idea / note`(捕获)、`status`(欠账查询)、`remind`(hook 专用,见 FR-10)、`assemble / review / commit`(结算,冷路径可转发给 Node/Python 实现)、`render`(视图重渲染)、`rebuild`(快照重放)。
- 捕获命令必须在任何仓库、任何目录可用;project 缺省取当前 git 仓库名。

#### FR-5:采集器接口(考古兜底)

- 接口:`collect(date, window) → 候选事件[]`,输出与 FR-2 事件同构,source 标记为 `archaeology:*`。
- 首批实现:codex 会话采集器(复用 V1 collector 的扫描、时区切分、截断与 skippedEvents 记账),git log 采集器(按 sha 与 inbox 去重后输出差集)。
- 语义约束:**候选永远不直接入账**,只能进入确认面的捞漏区,经用户点头后由提交器写入。
- 采集器出口做模式化脱敏(FR-12)。

#### FR-6:装配器

- 确定性,无模型调用。输入:inbox 中时间戳落在目标本地日的行 + 各采集器候选;输出:`day.json` 草稿(一手记录、捞漏候选、当前未结待办快照、账龄)。
- 本地日映射与跨 UTC 目录扫描继承 V1 的实现与测试。
- 按 sha / 归一化文本对一手记录与候选做确定性去重,剩余的疑似重复交给 FR-7。

#### FR-7:LLM 匹配层(可拔插)

仅两个职责:候选与一手记录、候选与未结待办之间的模糊匹配(文本变了但是同一件事,产出完成候选),以及两三句当日概览。输入输出均为小 JSON。失败或未配置时:匹配跳过(候选原样展示),概览用模板句("共 N 条记录覆盖 M 个项目")。模型与参数经环境变量/配置注入,不硬编码于文档或技能文本。

#### FR-8:确认面

- review 呈现在当前对话中,一屏、按一分钟预算设计:一手记录默认通过仅展示;需要点头的只有捞漏候选、历史待办完成候选、以及(收工模式下)当日新增待办的去留。
- **唯一可编辑物是 `confirmation.json`(补丁文件);review 文本与 day.json 草稿是视图,禁止直接编辑**——agent 的职责是把用户口头补丁("1和3算,2不要,5 改成 X,再记个想法 Y")翻译成 confirmation。
- 用户不回应、说"待会儿"或"跳过今天"时零成本退出,不纠缠。

#### FR-9:提交器

- 全系统唯一写 ledger 的组件。应用一份 confirmation 为一个事务:追加 ledger-log → 快照临时文件写入并 rename 原子替换 → 渲染 days 视图 → 标记该日已确认。
- 幂等:事务 id = 日期 + confirmation 内容哈希,重复应用无副作用。
- 中途失败不得留下半提交状态;快照与 log 不一致时以 log 为准(`wl rebuild`)。

#### FR-10:结算链触发点

提醒判定(`wl remind`):存在"已结束且未确认"的本地日,且该日有数据(inbox 有行或会话目录非空)→ 输出一行欠账摘要;无数据的日子自动标记 skipped;无欠账 → 输出为空(零注入)。积压多日时提醒合并为一行区间。

触发挂点(方案 A,已选):

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear",
        "hooks": [{ "type": "command", "command": "~/.worklog/hooks/remind.sh", "timeout": 5 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "~/.worklog/hooks/remind-daily.sh", "timeout": 5 }] }
    ]
  }
}
```

- `remind-daily.sh` 为纯 bash 快路径:当日标记文件存在即 `exit 0`(一次 stat),否则落标记后执行真实检查——每个本地日至多一次真实检查,跨天长会话由此覆盖。
- 注入体自带交互纪律,纪律不进全局 AGENTS.md:

```
[worklog] 昨日 7/25 有 9 条未确认记录。仅在答完用户当前请求后用一句话
附带提及;用户未回应则今日不再提。与当前任务无关时勿展开。
```

- 红线:不使用 PreToolUse / PostToolUse;hook 脚本秒级返回,故障静默(空输出),配置不带 statusMessage;提供 per-repo 关闭开关。
- 显式触发始终可用:`$power-work-report` 或口头请求、终端 `wl status`。
- 收工模式(可选):用户说"收工"时结算当日;确认后同日再产生的事件作为"已确认日的补充"在下次结算单列,补一句确认,不推翻已入账部分。
- 降级路径:方案 B = 仅 SessionStart + 捕获命令输出搭车提醒;方案 C = 提醒完全撤出 agent,`wl status` 挂 shell 提示符。三者均为一行配置的切换。

#### FR-11:日报形式

- **report.md 为正典,一屏纪律。** 结构:标题行(日期 · 项目数 · 条数 · 状态)→ 概览(两三句,全文唯一散文,FR-7 生成、模板兜底)→ 完成(每行 `[项目] 描述` + 行尾出处标记:短 sha / 会话标 / 手记标)→ 待办(新增 / 关闭 / 保留三段流转视图,保留段带账龄"最老挂 N 天")→ 想法 → 脚注(inbox 条数 · 捞漏确认数 · day.json 链接)。
- 刻意不设的区块及理由:"关键决策"不设——决策的家在 Decision Record 与 Issue,日报不做第二份拷贝;"风险与阻塞"不设——个人日志中即一条待办或 note;"明日优先"不设——明天的优先级是明天早上的决定;"项目进展"融入完成区前缀。每保留一个区块都在给每日确认与阅读加税。
- day.json 为数据本体;report.html 为可选视图,复用 V1 render.js(移除 routeSteps 等退役流程词汇)。
- 周报 / 月报 / 项目视图不是新功能,是同一渲染器对 ledger 不同时间切片的输出。
- 模板演进可追溯适用:改模板后 `wl render --all` 重渲染全部历史,git diff 呈现变化。

#### FR-12:隐私

采集器出口对候选文本做模式化脱敏(密钥、token、邮箱等常见模式),脱敏发生在候选进入确认面之前。inbox 以用户手写与 commit subject 为主,不强制脱敏但 `wl` 提供 `--redact` 选项。报告分享前自查的提醒保留于文档。

#### FR-13:逃生门

跳过今天(记 skipped,不再纠缠)、明天一起、多日批量补账(摘要压缩更狠,禁止把三天欠账变成长审讯)、per-repo 关闭提醒、方案 C 纯终端降级。任何逃生门的使用都不产生罪恶感设计(不显示"你已连续 N 天未记录"类文案)。

#### FR-14:V1 资产迁移

- collector.js → codex 会话采集器(改输出形状为 FR-2 候选事件);时区工程与全部相关测试保值。
- memory.json → 一次性导入为 ledger 初始状态。
- render.js → 视图层(day/period 渲染),移除退役流程词汇。
- V1 审查中的必修缺陷(--date 路径穿越、memory 非原子写、review 生成物被 render 静默覆盖、routeSteps 幽灵)在迁移中一并消除:前两者由 FR-9 / 参数校验内建,第三者由 FR-8 的"唯一可编辑物"接口消除,第四者随渲染迁移删除。
- power-work-report SKILL.md 的角色从"CLI 操作说明书"变为"确认对话驱动 + 触发行为"技能。

### 非功能需求

- 热路径延迟:捕获与提醒快路径为纯 bash;`remind-daily.sh` 快路径开销为一次文件 stat 量级;任何 hook 不得逼近其 timeout。
- 污染上限:干净日常态(无欠账)下,本系统在工作会话中的存在为零字节;最坏情况为每本地日一行注入 + 一轮数百 token 的确认对话。
- 提醒频率上限:每本地日至多一次,用户未回应当日不再提。
- 可用性:零 LLM 配置下捕获、装配、确认、入账、渲染全链路可用。
- 故障模型:捕获与提醒任何故障静默,绝不阻塞或拖慢用户的主工作;结算故障显式报错且不留半提交状态。
- 依赖:热路径零外部依赖(jq/python3 视为系统自带);冷路径允许 Node ≥18(复用 V1)。

## 已选方案

- 触发方案 A(SessionStart + UserPromptSubmit 日频标记)为默认,B/C 为一行配置的降级;选择依据:A 的剩余成本(数次系统调用)低于可感知阈值,B 存在"跨午夜、不重启、当日无捕获动作"的提醒迟到窄缝,C 将"顺口确认"降级为"自己记得开口"。
- 技术栈分层以调用频率为界:热路径 bash,冷路径复用 V1 Node 资产;不为统一而重写。
- 结算默认节奏推荐 D+1(一天过完才闭合),收工模式作为显式可选;最终默认见待定决策。
- 提醒纪律注入体随载荷下发,不占全局常驻;全局 AGENTS.md 仅保留口头触发词一行。

## 待定决策

以下为未决材料决策,实现前需确认,不得由实现自行落定:

1. **默认结算节奏:** D+1 开工确认(推荐)还是当日收工确认。两种均已支持,默认只能有一个。
2. **命名:** 根目录 `~/.worklog` 与命令名 `wl` 均为占位名;与 CODEX_HOME 体系的关系(独立目录,或挂 `~/.codex/` 下)。
3. **口头触发词表:** "记一下 / 记个待办 / 记个想法"为草案,最终词表由用户确认(影响 AGENTS.md 那一行)。
4. **收工模式触发词**(若启用):"收工"或其他。
5. **概览语言与 LLM 配置默认值**(zh-CN 默认沿用 V1;模型经 env 注入,无文档硬编码)。

## 范围外

- daemon、调度器、数据库、向量库、服务端、Web UI。
- 多用户、团队共享、云同步(git 仓库自理)。
- 自动关闭历史待办(完成候选永远 advisory,确认后才入账)。
- 读取 Codex `state_*.sqlite` 或任何其他工具的活状态。
- 工时统计、效率评分、连续打卡类度量。

## 验收标准

### AC-1:commit 即捕获

Given 已配置全局 core.hooksPath
When 在任意仓库完成一次非 merge commit
Then inbox 追加一条 type=done、source=commit:<sha> 的事件,无任何 agent 参与。

### AC-2:干净态零污染

Given 无未确认欠账日
When 新开会话或在长会话中发送 prompt
Then hook 输出为空,注入零字节,界面无状态消息。

### AC-3:跨天长会话准时提醒

Given 一个跨越多个本地日、既不重启也不 /clear 的会话,且存在欠账
When 每个本地日用户发送第一条 prompt
Then 恰好注入一次欠账提示;当日后续 prompt 不再触发真实检查(快路径 stat 后退出)。

### AC-4:提醒不改变对话次序

Given hook 已注入欠账提示
When agent 回复用户当前请求
Then 提示仅以答后附言形式出现一句;用户未回应则当日不再出现。

### AC-5:一手记录免确认

Given 当日 inbox 有一手记录且采集器有捞漏候选
When 呈现确认面
Then 一手记录仅展示不逐条询问;点头请求仅针对捞漏候选与完成候选。

### AC-6:口头补丁落盘

Given 用户以一句话给出混合确认("3 算,4 完成了,5 改文案,再记个想法")
When agent 处理该回复
Then 修改仅落于 confirmation.json;review 文本与 day.json 草稿未被直接编辑;重渲染后确认面反映补丁。

### AC-7:提交事务幂等

Given 同一份 confirmation
When 提交器被重复执行
Then ledger 状态与首次执行后一致,ledger-log 不出现重复事务。

### AC-8:快照可重放

Given ledger.json 被截断或损坏
When 执行 wl rebuild
Then 由 ledger-log 完整重建快照,与损坏前状态一致。

### AC-9:零 LLM 全链路可用

Given 未配置任何模型
When 执行装配、确认、提交、渲染
Then 全链路成功;候选原样展示,概览为模板句。

### AC-10:确认后补充事件

Given 某日已确认,当日又产生新事件
When 下次结算
Then 新事件作为该日补充单列请求确认,已入账部分不被推翻。

### AC-11:候选不越权入账

Given 采集器产出候选
When 用户未对某候选点头
Then 该候选不出现在 ledger 与已确认日报中。

### AC-12:视图可再生

Given 修改日报模板后执行全量重渲染
When 对比 git diff
Then 全部历史 report.md 更新为新模板,day.json 与 ledger 无任何变化。

### AC-13:逃生门无摩擦

Given 用户回复"跳过今天"或不回应
When 当日结束
Then 系统记录 skipped 或保持欠账,无追问、无负面文案;次日提醒合并为一行。

### AC-14:热路径无重语言

Given 捕获与提醒链路的全部脚本
When 审查实现
Then 不存在 Node/Python 进程启动(JSON 转义的单行 jq/python3 调用除外);冷路径组件仅由结算流程触发。
